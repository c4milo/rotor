# The ceilings the `calls` job of .github/workflows/ci.yml holds rotor's echo servers to: kernel
# calls per echo, as `bench/calls/count_calls.sh` counts them on GitHub's ubuntu-24.04 runners.
# `bench/calls/calls_gate.zig` says how the gate reads its three rounds.
#
# A line is: payload column ceiling candidate. The columns are the table's, by short name:
# enter (io_uring_enter), requests (io_uring requests), arms (poll arms), workers (io-wq jobs),
# reads, writes, ctl (epoll_ctl), waits (epoll waits) and other (other calls).
#
# Every ceiling comes from six runs of the job on 2026-09-24, five on AMD EPYC 7763 runners and
# one on an Intel Xeon Platinum 8370C, each the smallest of three rounds. It follows one of three
# rules:
#
# - A count every run gave as 0 has the ceiling 0.05, so any call of that kind a change adds fails.
# - A count whose runs differed by less than 0.1 has the highest run plus 0.10.
# - A count that moved with the runner's timing, such as io_uring_enter or how often a receive
#   found its bytes already there, has the highest run times 1.25 plus 0.10, rounded up to 0.05.
#   It catches a change that adds about a call per echo, and nothing smaller.
#
# To retake them, run the job, read the gate's "not gated" lines from each run, and apply the same
# rules. A row the file does not name is printed in this format and not judged.
